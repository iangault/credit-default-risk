# M4 Feature Engineering Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `make experiments` adds ten rows testing four groups of engineered features (each alone and all together) on `logreg_weighted` and `lgbm_weighted`, under the same stratified 5-fold CV, so each group's effect can be read against the M3 rows without features.

**Architecture:** A new `features.py` holds four feature groups (delinquency, payment, utilization, trend) as pure functions of a client's own row, plus a stateless `FunctionTransformer` step that adds the requested groups. `preprocess.py` learns to scale the new numeric columns and to split `utilization` into quantile bins in the encode step (fitted per fold). `Experiment` gets an optional `features` list; `pipeline.py` adds a `features` step first when it is set. The results table gets a `features` column.

**Tech Stack:** Python 3.12, conda, pandas, numpy, scikit-learn 1.9 (`FunctionTransformer`, `KBinsDiscretizer`), imbalanced-learn 0.14, LightGBM, pytest.

**Spec:** `docs/superpowers/specs/2026-09-25-credit-default-risk-design.md` (M4 row of the Milestones table). Feature ideas come from `notebooks/01-eda.ipynb`, section 6.

## Global Constraints

- Every command runs from the repo root with `conda run -n credit-risk` (or the env activated).
- Ownership: the spec lists M4 as the author's. On 2026-10-09 the author asked Claude to write all of M4 (plan, tests, code, docs), pausing after each task for review.
- **Annotations:** new and changed code carries explanatory comments in the style already in `src/`. The author asked specifically for an explanation of why logistic regression cannot follow the U-shape in utilization; it goes in `features.py`, in `build_encoder`'s comments, and in the M4 learning log entry.
- Author's decisions (2026-10-09): feature groups A to D below; EDA idea 3 (PAY_1 with 3+ grouped) dropped; each group alone plus all together; utilization also split into quantile bins learned per fold; `pay_ratio` uses `log1p`; models are `logreg_weighted` and `lgbm_weighted`.
- Feature definitions (exact):
  - delinquency: `months_late` = count of PAY_1..PAY_6 >= 1; `max_delay` = max of PAY_1..PAY_6.
  - payment: `pay_ratio` = log1p(PAY_AMT1 / BILL_AMT2) when BILL_AMT2 > 0, else 0; `no_bill` = 1 when BILL_AMT2 <= 0, else 0; `months_zero_pay` = count of PAY_AMT1..PAY_AMT6 == 0.
  - utilization: `utilization` = BILL_AMT1 / LIMIT_BAL.
  - trend: `util_change` = (BILL_AMT1 - BILL_AMT6) / LIMIT_BAL; `delay_trend` = mean(PAY_1..PAY_3) - mean(PAY_4..PAY_6).
- Utilization bins: `KBinsDiscretizer(n_bins=10, encode="onehot-dense", strategy="quantile", quantile_method="averaged_inverted_cdf")`, inside the encode step, so bin edges are learned on each training fold only. The raw `utilization` column stays as well.
- Same CV folds on train only; the test split is not read. Existing rows (M2, M3) must reproduce their committed metrics.
- SMOTENC combined with features is out of scope and is refused with a clear error (it would interpolate count columns such as `months_late`).
- No em dashes, plain factual tone, no unwarranted absolute words, in code comments and docs.
- Work on branch `m4-features`; do not push or merge without asking.

## Review Focus

- Division by zero or bad values: `BILL_AMT2` is 0 or negative for about 10% of clients, and bills can be negative. No feature should be NaN or infinite on the real data. Pinned in Task 1 (`test_no_missing_or_infinite_values_on_real_data`).
- A feature group typo in the config (e.g. `features: [delinquncy]`): should fail before any CV runs, listing valid names. Pinned in Task 4 (`test_unknown_feature_group_fails_when_building`).
- Utilization bins leaking across folds: bin edges must be learned inside the pipeline. Pinned by construction in Task 2 (bins live in `build_encoder`) and by `test_bins_are_one_hot_with_one_bin_per_row`.
- Combining `sampler: smotenc` with features: should fail with a message, not quietly create fractional counts. Pinned in Task 4 (`test_smotenc_with_features_is_refused`).
- Existing M2 and M3 rows changing: experiments without `features` must build the same pipeline as before. Pinned by the existing column-order test and checked against the committed table in Task 5.

Create `src/credit_risk/features.py`:

```python
"""Engineered features (M4): new columns built from each client's own row.

Each group adds a few columns that summarize information the raw columns hold
only indirectly. The groups come from the EDA (notebooks/01-eda.ipynb, section 6)
and the M4 line in the design spec:

- delinquency: months_late (count of PAY_1..PAY_6 >= 1) and max_delay (the worst
  PAY code). The EDA found these the strongest single signals (AUC 0.72 and 0.71).
- payment: pay_ratio, the share of the previous statement (BILL_AMT2) paid in
  PAY_AMT1, through log1p because a few clients pay many times their bill;
  no_bill, a flag for BILL_AMT2 <= 0, where the ratio has no meaning (set to 0);
  months_zero_pay, the number of months with no payment.
- utilization: BILL_AMT1 / LIMIT_BAL, how much of the credit limit is in use.
- trend: util_change, (BILL_AMT1 - BILL_AMT6) / LIMIT_BAL, whether debt grew over
  the six months; delay_trend, the mean PAY code of the latest three months minus
  that of the three before, whether the client is falling further behind.

Why utilization is also binned (in preprocess.build_encoder): the EDA showed a
U-shape. Default risk is higher for clients using almost none of their limit,
lowest around 1% to 13%, and highest at or over the limit. Logistic regression
gives each column one weight, so a column's effect on the log-odds of default is a
straight line: as utilization rises, predicted risk can only rise steadily or fall
steadily. A straight line can fit one side of the U, not both. Splitting
utilization into 10 bins, each a 0/1 column with its own weight, lets the model
give every range its own risk level and so follow the U step by step. Tree models
do not need this, since they can split utilization at several points; the raw
column is kept for them.

Every feature uses only the client's own row and learns nothing from other rows,
so adding them before the CV split cannot leak information between folds. (The bin
edges do learn from data, which is why they are fitted inside the pipeline.)
"""

from __future__ import annotations

from collections.abc import Iterable

import numpy as np
import pandas as pd
from sklearn.preprocessing import FunctionTransformer

from credit_risk.data import PAY_AMTS, PAY_STATUS

# group name -> the columns it adds, in order.
FEATURE_GROUPS: dict[str, tuple[str, ...]] = {
    "delinquency": ("months_late", "max_delay"),
    "payment": ("pay_ratio", "no_bill", "months_zero_pay"),
    "utilization": ("utilization",),
    "trend": ("util_change", "delay_trend"),
}
GROUP_NAMES = tuple(FEATURE_GROUPS)

# New columns that the encode step also splits into quantile bins (see docstring).
BINNED = ("utilization",)


def _delinquency(X: pd.DataFrame) -> dict[str, pd.Series]:
    pay = X[PAY_STATUS]
    # Code 1 and above means a payment was late. (Code 1 is rare after PAY_1, a quirk
    # noted in the EDA, so the count mostly reflects codes 2+ in earlier months.)
    return {"months_late": (pay >= 1).sum(axis=1), "max_delay": pay.max(axis=1)}


def _payment(X: pd.DataFrame) -> dict[str, pd.Series]:
    bill = X["BILL_AMT2"]
    has_bill = bill > 0
    # bill.where(has_bill) turns non-positive bills into NaN, so the division gives NaN
    # there instead of a divide-by-zero; fillna(0) then sets those ratios to 0.
    ratio = (X["PAY_AMT1"] / bill.where(has_bill)).fillna(0)
    return {
        "pay_ratio": np.log1p(ratio),  # log1p(x) = log(1 + x): 0 stays 0, big values shrink
        "no_bill": (~has_bill).astype(int),
        "months_zero_pay": (X[PAY_AMTS] == 0).sum(axis=1),
    }


def _utilization(X: pd.DataFrame) -> dict[str, pd.Series]:
    # LIMIT_BAL is never 0 (checked in the EDA). Negative bills give negative values.
    return {"utilization": X["BILL_AMT1"] / X["LIMIT_BAL"]}


def _trend(X: pd.DataFrame) -> dict[str, pd.Series]:
    recent, earlier = PAY_STATUS[:3], PAY_STATUS[3:]  # PAY_1-3 and PAY_4-6
    return {
        "util_change": (X["BILL_AMT1"] - X["BILL_AMT6"]) / X["LIMIT_BAL"],
        "delay_trend": X[recent].mean(axis=1) - X[earlier].mean(axis=1),
    }


_BUILDERS = {
    "delinquency": _delinquency,
    "payment": _payment,
    "utilization": _utilization,
    "trend": _trend,
}


def feature_columns(groups: Iterable[str]) -> list[str]:
    """Names of the columns the given groups add, in the order given.

    Raise ValueError naming the valid options if a group is not in GROUP_NAMES.
    """
    groups = list(groups)
    unknown = [g for g in groups if g not in FEATURE_GROUPS]
    if unknown:
        raise ValueError(
            f"Unknown feature group(s) {unknown}. Valid names: {', '.join(GROUP_NAMES)}"
        )
    return [column for g in groups for column in FEATURE_GROUPS[g]]


def add_features(X: pd.DataFrame, groups: Iterable[str]) -> pd.DataFrame:
    """Return a copy of X with the columns of each requested group appended."""
    groups = list(groups)
    feature_columns(groups)  # fail early on an unknown group name
    X = X.copy()  # leave the caller's DataFrame unchanged
    for group in groups:
        for name, values in _BUILDERS[group](X).items():
            X[name] = values
    return X


def build_feature_step(groups: Iterable[str]) -> FunctionTransformer:
    """A pipeline step that adds the given groups. It learns nothing, so fit does nothing."""
    # FunctionTransformer wraps a plain function as a pipeline step; kw_args are passed
    # to it on every call. A tuple, so the step's settings cannot be changed afterwards.
    return FunctionTransformer(add_features, kw_args={"groups": tuple(groups)})
```

```python
def build_scaler(extra_numeric: Sequence[str] = ()) -> ColumnTransformer:
    """Step 1, a fresh unfitted ColumnTransformer: scale NUMERIC, pass the codes through.

    `extra_numeric`: engineered columns (features.py) to scale along with the amounts.
    """
    scaler = make_column_transformer(
        (StandardScaler(), [*NUMERIC, *extra_numeric]),
        # Left as raw codes here; build_encoder one-hot encodes CATEGORICAL later,
        # after any resampling.
        ("passthrough", CATEGORICAL + ORDINAL),
        remainder="drop",  # drops ID
        verbose_feature_names_out=False,
    )
    # pandas output keeps the column names, which SMOTENC uses to find the
    # categorical columns.
    return scaler.set_output(transform="pandas")


def build_encoder(
    extra_numeric: Sequence[str] = (), binned: Sequence[str] = ()
) -> ColumnTransformer:
    """Step 2, a fresh unfitted ColumnTransformer: one-hot CATEGORICAL, pass the rest through.

    Expects the output of build_scaler (or of a resampler placed after it).
    `extra_numeric`: engineered columns to pass through. `binned`: columns (already
    in extra_numeric) to also split into quantile bins.
    """
    parts = [
        # Listing each group (instead of remainder="passthrough") keeps the column
        # order fixed: amounts, engineered columns, one-hot columns, bins, PAY codes.
        ("passthrough", [*NUMERIC, *extra_numeric]),
        (
            OneHotEncoder(drop="if_binary", handle_unknown="ignore", sparse_output=False),
            CATEGORICAL,
        ),
    ]
    if binned:
        # Why bins (M4): logistic regression gives each column one weight, so the
        # column's effect on the log-odds of default is a straight line. Utilization
        # has a U-shaped link to default (higher at near-zero use, lowest around 1% to
        # 13%, highest at or over the limit), and a straight line can follow only one
        # side of a U. Ten bins, each a 0/1 column with its own weight, let the model
        # give each range its own risk level. "quantile" puts about the same number of
        # clients in each bin. The edges are learned when the pipeline is fitted, so in
        # cross-validation they come from the training folds only. The bins are cut
        # from the scaled column, which gives the same bins as the raw one.
        parts.append(
            (
                KBinsDiscretizer(
                    n_bins=10,
                    encode="onehot-dense",
                    strategy="quantile",
                    quantile_method="averaged_inverted_cdf",
                ),
                list(binned),
            )
        )
    parts.append(("passthrough", ORDINAL))
    encoder = make_column_transformer(
        *parts, remainder="drop", verbose_feature_names_out=False
    )
    return encoder.set_output(transform="pandas")
```

    # Engineered columns this experiment adds (empty when it lists no features).
    # Raises ValueError on a typo like "delinquncy", before any fitting starts.
    extra = feature_columns(experiment.features)
    binned = [c for c in BINNED if c in extra]  # e.g. utilization, when its group is on
    if extra and experiment.sampler == "smotenc":
        # SMOTENC would interpolate count columns such as months_late into values like
        # 2.4. Supporting it means listing those columns as categorical in samplers.py;
        # no experiment needs it yet.
        raise ValueError("sampler 'smotenc' cannot be combined with features yet")

    # `steps` is a list of (label, step) pairs, run in list order.
    steps = []
    if extra:
        steps.append(("features", build_feature_step(experiment.features)))
    steps.append(("scale", build_scaler(extra)))
    # experiment.sampler is the `sampler:` value from the config line, or None when the
    # line has none. Only experiments that name a sampler get a resample step.
    if experiment.sampler is not None:
        # Raises ValueError on a typo like "smote", before any fitting starts.
        steps.append(("sample", get_sampler(experiment.sampler, seed)))
    # Every experiment ends the same way: one-hot encode (and bin), then the model.
    steps += [("encode", build_encoder(extra, binned)), ("model", model)]
    # Steps are named by hand (make_pipeline would name them after their classes) so
    # other code can ask for pipe.named_steps["model"] whatever the model is.
    return Pipeline(steps)
